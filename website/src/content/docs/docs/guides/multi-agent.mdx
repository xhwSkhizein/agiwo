# Multi-Agent

Agiwo supports two public ways to compose agents: agent-as-tool composition and
scheduler-managed orchestration. Session chat uses `MainAgent.accept` separately.

## Choose the right level

### Use `Agent.as_tool()` when

- one agent should delegate focused sub-work to another
- the child can behave like a normal tool call
- you do not need persistent child state between turns

### Use `Scheduler` when

- roots must stay alive across multiple inputs
- agents need waiting and wake conditions
- you need cancel / shutdown / Worker waitset
- the runtime should manage child lifecycles directly

## Agent-as-tool

```python
from agiwo.agent import Agent, AgentConfig
from agiwo.llm import OpenAIModel

researcher = Agent(
    AgentConfig(
        name="researcher",
        description="Research specialist",
        system_prompt="Research thoroughly and cite sources.",
    ),
    model=OpenAIModel(name="gpt-5.4"),
)

orchestrator = Agent(
    AgentConfig(
        name="orchestrator",
        description="Delegates focused research",
        system_prompt="Delegate independent research tasks to the researcher tool.",
    ),
    model=OpenAIModel(name="gpt-5.4"),
    tools=[researcher.as_tool()],
)
```

This is the simplest public composition path when the delegated unit should look
like a functional tool.

## Scheduler-managed orchestration

```python
from agiwo.scheduler import Scheduler

async with Scheduler() as scheduler:
    await scheduler.register_worker_parent(
        state_id=orchestrator.id,
        session_id="sess-1",
        agent=orchestrator,
    )
    await scheduler.enqueue_input(
        orchestrator.id,
        "Research two competing approaches and compare them.",
        agent=orchestrator,
    )
    result = await scheduler.wait_for(orchestrator.id)
    print(result.response)
```

For longer-lived roots, call `enqueue_input` again after the root returns to
`IDLE` (or while `RUNNING` / `WAITING` / `QUEUED` to feed the live Loop /
USER_HINT mailbox).

## Scheduler runtime tools

Agents running under the scheduler automatically get orchestration tools such
as:

- `spawn_child_agent`
- `fork_child_agent`
- `query_spawned_agent`
- `sleep_and_wait`
